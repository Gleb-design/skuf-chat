## 2. СТЕК
- Backend: Node.js, Express, Socket.io, HTTP server
- Frontend: чистый HTML/CSS/vanilla JS
- Хранение: RAM + Redis (Render Key Value, free tier)
  • История флудилки — в Redis (Sorted Set, TTL 24ч), fallback в RAM
- Хостинг: Render (free Web Service). Может "засыпать" после простоя.

## 3. АРХИТЕКТУРА ЧАТОВ
- generalMessagesBox — общая флудилка (комната 'general')
- privateMessagesBox — приватные 1-на-1 (комнаты room_<id>_<id>)
- История общей флудилки — в Redis (Sorted Set skuf:history, TTL 24ч),
  fallback в RAM (globalMessagesHistory)
- Кастомные ники — в Redis (String skuf:nick:<sessionKey>), БЕЗ TTL.
  При подключении клиент шлёт sessionKey (из localStorage), сервер подтягивает ник.
  Fallback в RAM не реализован (для ников он не нужен — на проде всегда Redis).
- Статистика — в Redis: Hash skuf:stats:<YYYY-MM-DD> (messages, peakOnline)
  + Set skuf:stats:users:<YYYY-MM-DD> (уникальные sessionKey). TTL 7 дней.
  Fallback в RAM (ramStats + Set users), обнуляется при смене суток UTC.
- Очистка каждые 30 мин
- При подключении — новому пользователю отправляется история

- REPLY (v1.19.0): у каждого сообщения есть messageId (msg_<ts>_<rand6>).
  В messageData — senderSessionKey, timestamp, replyTo. Всё в Redis.
  Клиент шлёт { text, replyTo } в send_global_msg (объект, не строка).
- ПРИГЛАШЕНИЯ В ПРИВАТ (v1.20.0): Map sessionsByKey (sessionKey → socket),
  заполняется в init_session, чистится в disconnect. Антиспам 1/10сек.
  События: invite_private, private_invite, private_invite_response,
  invite_sent, invite_error, private_invite_declined.

### Перевода сообщений / GlobeSkuf (v1.17.0)
- Кнопка 🌐 под каждым ЧУЖИМ сообщением (incoming). Своего — нет.
- Клик по кнопке → под оригиналом появляется перевод (серым курсивом,
  отделён пунктирной линией). Повторный клик → скрыть. Ещё клик → показать
  из кэша DOM (data-translated), без запроса к серверу.
- Сервер: socket-событие 'translate_message' { text, targetLang }
  → 'translated_message' { original, translated, detectedLang, targetLang }
  → 'translate_error' { error: 'too_long' | 'api_failed', original }
- Язык перевода: клиент берёт из navigator.language (2 первые буквы),
  шлёт в targetLang. Русский видит перевод на русский, англичанин — на английский.
- API: цепочка из 3 источников, все БЕЗ API-ключа:
  1) lingva.ml (прокси Google, https://lingva.ml/api/v1/auto/<tl>/<text>)
  2) MyMemory (api.mymemory.translated.net, лимит ~5000 символов/день)
  3) Google напрямую (translate.googleapis.com/translate_a/single?client=gtx)
- ВАЖНО (v1.17.1): каждый источник проверяется на translated !== text.
  Если вернул исходник — пропускаем, идём к следующему. Это критично,
  потому что на Render lingva иногда отдаёт оригинал без перевода.
- Google напрямую с Render-IP отдаёт 429 (бан по IP, не по заголовкам).
  Поэтому он — последний фолбэк. Локально Google работает как основной.
- Node.js 18+ — fetch встроенный.
- Кэш переводов на сервере: Map в RAM, ключ `${targetLang}:${text}`,
  максимум 500 записей (FIFO). Улетает при рестарте — не критично.
- Ограничения: текст > 500 символов → 'too_long'. Если все источники
  не сработали → 'api_failed'.
- Клиентский матчинг: при получении 'translated_message' пробегаем все
  .message.incoming, ищем p.textContent === original, вставляем перевод
  в .translated-text этого сообщения.
- Файлы: public/client.js (userLang, toggleTranslate, обработчики
  translated_message / translate_error, кнопка 🌐 в receive_msg),
  public/style.css (.translate-btn, .translated-text, .hidden),
  server.js (translateText + кэш + saveTranslation, socket.on('translate_message')),
  public/sw.js (CACHE_NAME → skuf-chat-v6).

### АНГЛИЙСКАЯ ВЕРСИЯ (обсуждено, на подумать)

**Зачем:** открыть доступ к мировой аудитории (Reddit r/CasualConversation,

Русскоязычная аудитория ограничена, англоязычная — в разы больше.

**Варианты реализации (от простого к сложному):**

1. **Двуязычный интерфейс (i18n) — простой старт.**
   - Переключатель языка в шапке (🇷🇺 / 🇬🇧).
   - Все тексты интерфейса (кнопки, плейсхолдеры, системные сообщения)
     выносятся в отдельный файл локализации (например, public/i18n.js).
   - Язык сохраняется в localStorage, применяется при загрузке.
   - Чат ОБЩИЙ — русские и англичане в одной комнате, каждый видит
     интерфейс на своём языке. Сообщения пользователей, разумеется,
     на языке автора (тут без перевода).
   - Плюс: просто, дёшево, не надо трогать серверную логику.
   - Минус: языковой барьер в чате — русский и англичанин не поймут друг друга.

2. **Разделение на две комнаты: ru и en.**
   - При входе выбор языка → попадаешь в свою комнату ('general_ru' / 'general_en').
   - Рулетка работает внутри языковой группы (русский ищет русского).
   - История — отдельная для каждой комнаты (ключ в Redis: skuf:history:ru / :en).
   - Статистика — общая или раздельная (обсудить).
   - Плюс: нет языкового барьера, каждый общается на своём.
   - Минус: критическая масса пользователей делится на 2, в каждой комнате
     онлайн меньше. На старте может быть пусто.

3. **Гибрид: общая комната + языковые теги.**
   - Один общий чат, но у каждого сообщения есть тег языка.
   - Фильтр в UI: «показать только 🇷🇺» / «только 🇬🇧» / «все».
   - Рулетка — по выбору языка.
   - Плюс: и общая масса, и разделение.
   - Минус: сложнее всего в реализации.

- СНАЧАЛА — Вариант 1 (i18n + переключатель). Минимум работы, сразу видно,

## 20. МОРСКОЙ БОЙ (v1.22.0–v1.23.0)

### Архитектура (v1.23.0 — после рефактора)
- **Роутер:** `game-server.js` — универсальный (см. раздел 21).
- **Модуль игры:** `games/battleship.js` — логика Морского боя.
- **Контракт:** id, name, minPlayers, maxPlayers, createInitialState,
  handleAction, isFinished, serializeFor.
- **События:** модуль возвращает, роутер рассылает по to:
  self/opponent/both/player1/player2.
- **Роутер хранит:** game.module, game.state, game.phase.
- **Таймеры, чат, приглашения, disconnect** — в роутере.
- **Клиент:** `public/game.js` (IIFE, использует глобальный `socket`
  из client.js). Загружается ПОСЛЕ client.js.
- **Хранилище игр:** RAM, `Map<gameId, GameState>` + `Map<socketId, gameId>`.
  Улетает при рестарте Render — не критично, игры короткие.
- **Поле:** 10×10. Корабли: 1×4, 2×3, 3×2, 4×1 (классика).
⚠️ v1.26.2: во все игровые события (game_invited, game_invite_sent,
game_started, game_finished, game_placing) добавлено поле
gameType: 'battleship' | 'domino' | 'tanks'. Каждый клиент
фильтрует события по своему gameType, чтобы чужие оверлеи
не открывались.

### Фазы игры
1. **waiting** — приглашение отправлено, ждём accept/decline.
2. **placing** — оба игрока расставляют корабли.
3. **battle** — по очереди стреляют.
4. **finished** — игра окончена, есть победитель.

### События (client → server)
| Событие | Payload | Что делает |
|---|---|---|
| `game_invite` | — | Пригласить партнёра из привата |
| `game_accept` | `{ gameId }` | Принять приглашение |
| `game_decline` | `{ gameId }` | Отклонить |
| `game_place_ships` | `{ gameId, random?: true, board?: 2D }` | Расстановка |
| `game_shot` | `{ gameId, x, y }` | Выстрел |
| `game_chat` | `{ gameId, text }` | Сообщение в мини-чат |
| `game_leave` | `{ gameId }` | Выйти из игры |

### События (server → client)
| Событие | Payload | Когда |
|---|---|---|
| `game_invited` | `{ gameId, fromUsername }` | Пришло приглашение |
| `game_invite_sent` | `{ gameId, toUsername }` | Приглашение ушло |
| `game_declined` | `{ byUsername }` | Тебе отказали |
| `game_placing` | `{ gameId }` | Оба приняли, фаза расстановки |
| `game_board_accepted` | `{ gameId, board }` | Твоё поле принято |
| `game_battle` | `{ gameId, turn, youAre, myBoard, enemyBoard, opponentName }` | Оба готовы, бой начался |
| `game_shot_result` | `{ x, y, result, turn }` | Результат твоего выстрела |
| `game_opponent_shot` | `{ x, y, result, turn }` | Соперник стрелял |
| `game_chat_msg` | `{ from, fromUsername, text, timestamp }` | Сообщение в чате |
| `game_finished` | `{ winner: 'you'/'opponent', reason }` | Игра окончена |
| `game_error` | `{ reason }` | Ошибка |

### Результаты выстрела
- `miss` — мимо (синяя точка).
- `hit` — попал (красная клетка с 🔥).
- `sunk` — потопил (тёмно-красная клетка с ☠️).
- При `sunk` клетки вокруг корабля автоматически помечаются как `auto-miss`.

### Передача хода
- Промах (`miss`) → ход переходит сопернику.
- Попадание (`hit`) / потопление (`sunk`) → ход остаётся у стрелка.

### Таймеры
- **IDLE_TIMEOUT_MS = 60 сек** — на ход. Если игрок не ходит, техпоражение.
- **RECONNECT_GRACE_MS = 20 сек** — реализовано в v1.22.13 (MVP).
  При disconnect игрока — НЕ endGame, а таймер 20 сек. Соперник видит
  «⚠️ Ждём 20 сек...». Если игрок вернулся — игра продолжается.
  Если нет — endGame(disconnect).
  ⚠️ Работает для обрыва интернета. НЕ работает для F5 (клиент не
  восстанавливает оверлей — нет game_reconnect с полным состоянием).
  Детали — раздел 15, v1.22.13.

### Античит
- Клиент НЕ получает расположение кораблей соперника. Только результат
  каждого выстрела (hit/miss/sunk).
- Сервер проверяет: чей ход, координаты в пределах поля, клетка не обстреляна.
- Валидация присланного `board` от клиента — НЕ реализована пока
  (заглушка: генерируется случайное поле). Полная валидация + ручная
  расстановка — в бэклоге.

### UI-элементы (в index.html, внутри gameOverlay)
- `.game-header` — заголовок + кнопка ✖ выхода.
- `.game-info` — имя соперника + индикатор хода.
- `.game-boards` — два поля рядом (на мобилке — друг под другом).
- `.game-controls` — кнопки «Расставить случайно» / «Готов» + статус.
- `.game-chat` — мини-чат с логом + полем ввода.

## 21. МОДУЛЬНАЯ АРХИТЕКТУРА ИГР (v1.23.0)

### Зачем
Сейчас есть Морской бой. Планируются: Домино, Точки, Шашки.
Без модульной архитектуры game-server.js превратится в кашу
(switch по типу игры в каждом socket.on).

### Как устроено
- game-server.js — универсальный роутер:
  • хранит игры (games Map, socketToGame)
  • приглашения, accept/decline, disconnect, reconnect
  • idle timer (60с), мини-чат
  • вызывает методы модуля игры и рассылает события
  • НЕ знает правил игр

- games/<game>.js — модуль конкретной игры:
  • чистые функции (без socket.io, без io.emit)
  • возвращает события — роутер их сам рассылает
  • знает только про game.state и playerKey

### Контракт модуля
module.exports = {
    id: 'battleship',                     // уникальный ID
    name: '🚢 Морской бой',                // отображаемое имя
    minPlayers: 2,
    maxPlayers: 2,

    createInitialState: (player1, player2) => ({...}),
    handleAction: (game, playerKey, action, payload) => ({
        ok: true,
        events: [
            { to: 'self',     event: 'game_board_accepted', data: {...} },
            { to: 'opponent', event: 'game_opponent_shot',  data: {...} },
        ],
        finished: false,        // опционально
        winner: null,           // если finished
        reason: null,           // если finished
    }),
    isFinished: (game) => ({ finished, winner, reason }),
    serializeFor: (game, playerKey) => ({...}),
};

### Реестр игр в game-server.js
const GAMES = {
    battleship: require('./games/battleship'),
    domino:     require('./games/domino'),
    // dots:     require('./games/dots'),    (в будущем)
    // checkers: require('./games/checkers'), (в будущем)
};

### События от модуля — адресация
| to          | Кому                            |
|-------------|----------------------------------|
| 'self'      | тому, кто сделал действие        |
| 'opponent'  | сопернику                        |
| 'both'      | обоим                            |
| 'player1'   | конкретно player1                |
| 'player2'   | конкретно player2                |

Роутер преобразует 'self'/'opponent' в socketId через game.player1/player2.

### Что осталось в роутере (не в модуле)
- Создание игры (game_invite)
- Приглашения (game_accept, game_decline)
- Мини-чат (game_chat) — общий для всех игр
- Disconnect / reconnect grace (20 сек)
- Idle timer (60 сек)
- Endgame (game_finished)

### Как добавить новую игру
1. Создать games/<game>.js с контрактом выше.
2. Добавить в GAMES в game-server.js.
3. Создать клиентский UI (отдельно — public/game-<game>.js).
4. Добавить пункт в модалку #gameMenuModal (data-game="<game>").

⚠️ Клиенты отдельных игр: public/game.js (battleship),
public/domino.js (domino). Универсальный клиент — задача на будущее.
Меню (public/game-menu.js) — общее, только emit('game_invite', { gameType }).

## 22. ТАНЧИКИ 1-НА-1 (v1.25.0–v1.26.0)

### Что это
Классика Battle City, адаптированная под дуэль 1-на-1.
Поле 13×13, у каждого своя база в углу. Цель — уничтожить базу
соперника или все его жизни.

### Архитектура
- **Модуль:** games/tanks.js (серверная логика).
- **Клиент:** public/tanks.js + public/tanks.css.
- **Роутер:** game-server.js (универсальный, уже знает про tanks).
- **Хранение:** RAM, как у других игр (улетает при рестарте).

### Контракт модуля (как у battleship/domino)
- id: 'tanks', name: '🛡️ Танчики', minPlayers: 2, maxPlayers: 2
- createInitialState(player1, player2) — карта + танки + базы + inputs.
  ⚠️ player1/player2 — ОБЪЕКТЫ {socketId, username}, не строки!
  Ключи в tanks/bases/inputs — жёстко 'player1'/'player2'.
- handleAction(game, playerKey, action, payload) — работает с game.state.
  Сейчас единственное действие: 'input' → обновляет inputs[playerKey].
- isFinished(game) — вызывается со state, пока всегда false.
- serializeFor(game, playerKey) — вызывается и с обёрткой (game_accept),
  и с самим state (startGameLoop). Внутри: const state = game.state || game.
- tickGame(state) — вызывается роутером как module.tickGame(game.state).
  Продвигает игру на 1 тик.

### Поле
- MAP_SIZE = 13. Клетка рендерится 50×50 (Canvas 650×650).
- Тайлы: TILE_EMPTY=0, TILE_BRICK=1, TILE_STEEL=2, TILE_WATER=3,
  TILE_BUSH=4, TILE_BASE=5.
- Рамка бетона по периметру. Базы P1_BASE=(1,11), P2_BASE=(11,11).
- Танки: P1_SPAWN=(1,10), P2_SPAWN=(11,10). Смотрят вверх.
- Симметрия карты относительно центра (поворот на 180°).

### Константы движения
- TANK_SPEED_TICKS = 5 (1 клетка за 250 мс при 20 Гц).
- BULLET_SPEED_TICKS = 1 (пока не используется).
- RESPAWN_TICKS = 40 (2 сек) — тоже пока не используется.
- BATTLE_TIMEOUT_MS = 5 мин (пока не подключено).

### Игровой цикл на сервере
- startGameLoop(game) в game-server.js: setInterval 50 мс.
- Каждый тик: tickGame → isFinished → serializeFor для обоих →
  emit('game_tick', { gameId, state }).
- Останавливается в endGame или при выходе из фазы 'battle'.

### Управление
- Десктоп: WASD (или стрелки) + Space. Клавиши зажатые — хранятся.
- Клиент шлёт game_action { gameId, action: 'input', data: {up,down,
  left,right,shoot} } каждые 50 мс, если inputDirty.
- Мобилка: не реализована (отложена).
