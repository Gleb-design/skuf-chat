## 1. ТЕКУЩИЙ СТАТУС
- Production: https://skuf-chat.onrender.com
- GitHub: Gleb-design/skuf-chat (ветка main)
- Render: Live
- Локальный запуск: npm start → http://localhost:3000
- Стабильная версия: v1.13.1
- Хранение: RAM + Redis (Render Key Value, free tier)
  • История флудилки — в Redis (Sorted Set skuf:history, TTL 24ч)
  • Fallback в RAM, если Redis недоступен
  • Redis URL: Internal (redis://red-dajr9t9594qs73dauj50:6379) в Environment

## 2. СТЕК
- Backend: Node.js, Express, Socket.io, HTTP server
- Frontend: чистый HTML/CSS/vanilla JS
- Хранение: RAM + Redis (Render Key Value, free tier)
  • История флудилки — в Redis (Sorted Set, TTL 24ч), fallback в RAM
- Хостинг: Render (free Web Service). Может "засыпать" после простоя.

## 3. АРХИТЕКТУРА ЧАТОВ
- generalMessagesBox — общая флудилка (комната 'general')
- privateMessagesBox — приватные 1-на-1 (комнаты room_<id>_<id>)
- История общей флудилки — в Redis (Sorted Set skuf:history, TTL 24ч),
  fallback в RAM (globalMessagesHistory)
- Кастомные ники — в Redis (String skuf:nick:<sessionKey>), БЕЗ TTL.
  При подключении клиент шлёт sessionKey (из localStorage), сервер подтягивает ник.
  Fallback в RAM не реализован (для ников он не нужен — на проде всегда Redis).
- Статистика — в Redis: Hash skuf:stats:<YYYY-MM-DD> (messages, peakOnline)
  + Set skuf:stats:users:<YYYY-MM-DD> (уникальные sessionKey). TTL 7 дней.
  Fallback в RAM (ramStats + Set users), обнуляется при смене суток UTC.
- Очистка каждые 30 мин
- При подключении — новому пользователю отправляется история

## 4. РУЛЕТКА 1-НА-1
- Переменная waitingSkuf (глобальная)
- События: search_private, waiting, private_found, send_private_msg, leave_private, next_skuf, partner_disconnected
- При поиске пользователь выходит из general
- Автовозврат в general через ~3 сек после partner_disconnected

## 5. КНОПКИ В РУЛЕТКЕ
- btnNextSkuf ("🔄 Следующий скуф") — эмитит next_skuf
- btnCancelSearch ("❌ Выйти во флудилку") — эмулирует клик по btnGeneral

## 6. ЗВУКИ
- click.mp3 (своё сообщение) — volume 0.3
- beer.mp3 (чужое сообщение) — volume 0.5
- Кэшируются в service worker (skuf-chat-v2)

## 7. RATE LIMIT
- 5 сообщений за 3 секунды (RATE_LIMIT_MAX=5, RATE_LIMIT_WINDOW_MS=3000)
- Функция isRateLimited(socket) в server.js

## 8. МОДЕРАЦИЯ (новое в v1.3.3)
- Стоп-лист рекламы: BAN_PATTERNS в server.js (t.me/, казино, ставки, крипта, 1xbet и т.п.)
- Функция containsAds(text) — если true, socket.emit('msg_blocked', {reason:'ads'})
- Антифлуд повторов: REPEAT_WINDOW_MS = 30 сек, REPEAT_MAX = 3
- Функция isRepeated(socket, text) — если true, socket.emit('msg_blocked', {reason:'repeat'})
- Мат НЕ фильтруется (это часть атмосферы!)
- Проверки в send_global_msg и send_private_msg — после isRateLimited, до создания messageData
- Клиент: обработчик msg_blocked показывает плашку

## 9. СЧЁТЧИК ОНЛАЙН
- Переменная onlineCount, broadcastOnlineCount() через io.emit('online_count')

## 10. ИНДИКАТОР "СКУФ ПЕЧАТАЕТ..."
- Клиент: input на messageInput, throttle 1.5 сек, socket.emit('typing')
- Сервер: if privateRoom → socket.to(privateRoom), иначе socket.to('general')
- Клиент: socket.on('partner_typing') → показывает #typingIndicator на 2 сек

## 11. OPEN GRAPH + PWA
- og:title, og:description, og:image (og-image.png 1200x630), Twitter Cards
- PWA: manifest.json, sw.js, CACHE_NAME = 'skuf-chat-v2'
- Иконка 512x512

## 12. НИКИ
- Собираются на сервере из skufNames + skufStatus + skufEmojis
- Примеры: "🍺 Кабан (главный по шашлыкам)"

## 17. ОСОБЕННОСТЬ RENDER
Free Web Service засыпает после простоя. Первый запрос может грузиться 20-30 сек.
Free PostgreSQL удаляется через 30 дней — для монетизации не подходит!
Render Key Value (Redis) — free tier, подходит.
